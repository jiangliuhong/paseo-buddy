Paseo Buddy is a native macOS Swift/AppKit floating monitor for Paseo agents. Red numbers show running agents, green numbers show completed unread agents, and the expanded list groups running, completed unread and permission-blocked agents. Rows show project, workspace, agent name, status and available elapsed time. The compact pill uses a segmented toolbar with red running and green unread corner badges at the top right; a separate translucent panel groups agent cards. Click to expand/collapse, drag to reposition anywhere on the full screen including the Dock area, or right-click for Quit and keyboard focus. Tab focuses the pill and Shift-F10 opens the controls menu. With controls focused, Space/Return toggles the list and Escape closes it. Opacity, size, icon/text visibility and a custom single-line label persist in Paseo. These controls live under **悬浮窗口 → 外观**; custom text is applied after **保存文本**. Both count badges hide at zero, and hidden content reserves no blank space. Disconnection still shows an unknown-count dash. If the icon, text and both badges are absent, a small clickable capsule remains. Opening Buddy never automatically marks agents read. Use **Mark as read** on an unread completion to synchronize its read state with Paseo; the card disappears only after the daemon updates it. **Open in Paseo** has a rounded hover highlight and hand cursor.

## Installation and first build

Install and enable the plugin through Paseo Settings → Plugins using `git:jiangliuhong/paseo-buddy`, or run `paseo plugin add git:jiangliuhong/paseo-buddy`. Requires Paseo ≥ 0.11.1, npm for plugin preparation, macOS 13+, and Apple Command Line Tools or Xcode on the daemon machine. The daemon must run in the local logged-in macOS desktop session. A remote server cannot place a window on the client device. Other platforms cannot build/start the companion.

Enabling the plugin **does not compile or download an application**. Open Settings → Plugins → Paseo Buddy → 悬浮窗口 and select **Build and start native companion**. Review the native version, bundled source location and SHA-256, architecture and developer-tool requirement. Only **Confirm build and start** authorizes local compilation and launch. **Cancel** performs neither. Confirmation expires after five minutes, is single use, and is revoked on cancellation, stop or plugin disable. Failed builds need a fresh confirmation to retry.

## Source and native implementation

The native version is `0.1.3-native.1`. Its full Swift/AppKit source is embedded at `server/native-source.ts` and included in the plugin's Git source and server bundle. The source hash changes when the native implementation changes. **No Companion binary is downloaded from a Release or other URL.** The independent native process is necessary for a floating desktop window outside Paseo's plugin surfaces; Electron/Chromium, DMG/ZIP acquisition and extraction are removed.

After confirmation, the plugin invokes fixed Apple tools without a shell: `/usr/bin/xcode-select -p`, then `/usr/bin/xcrun swiftc` with AppKit, a fixed macOS 13 deployment target, the selected architecture and private build paths. It does not install Command Line Tools, prompt for administrator privileges, modify system tools, change quarantine or bypass OS protections. Install missing development tools yourself using Apple's official instructions. First compilation may take several minutes and needs additional disk space for temporary compiler modules.

The native cache is `~/Library/Caches/Paseo Buddy/native/<native-version>-<arch>-<source-hash-prefix>-<build-recipe>`. A build manifest records the version, architecture, source SHA-256 and executable SHA-256. The compiler writes to a private temporary directory and publishes atomically after success; failed/cancelled temporary builds are removed. The app is locally built; it is not an Apple Developer signed/notarized distributed application. This removes the separately distributed Electron artifact, but the source/build/start behavior still requires Registry review.

## Start, stop and rebuild

A valid cache matching the current source/architecture and binary hash starts automatically when the plugin is enabled or Paseo restarts, with no compilation or confirmation. **Start cached companion** only reuses a valid cache; it cannot compile. Source changes or a missing cache require the separate build action and confirmation.

**Stop companion** cancels pending startup/build and waits for the owned child to terminate. Disabling the plugin does the same; later re-enable can start its valid cache. Right-click Quit closes the native window while leaving the plugin available. A shared native file lock prevents duplicate windows using the same cache root. A separately started development window has its own root and must be quit separately. EOF on the inherited pipe or disappearance of the parent causes native exit.

To rebuild a corrupt cache, first stop Buddy and quit independently started copies. Remove only the specific version/architecture/source directory named in the settings error from the native cache root, then review and confirm a build again. Unknown/corrupt cache contents are retained for explicit repair; the plugin does not delete them automatically. Older native builds and legacy `companions` Electron caches are not pruned or launched. Legacy Electron binaries do not satisfy native cache validation; quit any old running copy manually. Existing Paseo opacity/size preferences are retained, while native window positions use a separate preferences domain.

## Data access and recovery

The plugin's Node process connects only to the selected local Paseo home's loopback TCP endpoint using its existing local credential. It keeps that credential in memory and re-reads it during reconnect. Only normalized project/workspace/name/status/timestamp data passes through stdin to the native child; no credential, daemon path or full working directory is sent. The native process has no HTTP server, daemon credential reader or arbitrary command execution interface. A bounded stdout message allows only an explicit mark-read action for a displayed completion; Node validates the current completion, executes the installed SDK attention operation and sends a fixed result back. The daemon plugin's paginated snapshot RPC remains read-only. On disconnect, stale agents are cleared and fresh authoritative subscription snapshots restore the state after reconnect.

If build/start fails, inspect the settings error and `paseo plugin logs paseo-buddy`. Check `xcode-select -p`, `xcrun swiftc --version`, local macOS desktop session, free disk space and cache permissions. A minimal `import AppKit` compilation is a useful toolchain check. The plugin does not repair system developer tools automatically. Retry transient failures with a fresh build confirmation; do not disable OS security controls. Native Intel execution, VoiceOver, multi-display/full-screen behavior and live daemon restart still need manual acceptance. Completion/failure notification delivery is implemented; actual macOS authorization and banners still need GUI acceptance. Right-click the pill → **Enable completion notifications…** to grant system permission. Only live terminal events with explicit turn IDs notify; snapshots, canceled turns and events missed during disconnect/loading are not replayed. Permission denial never blocks the overlay. Rows provide **Open in Paseo** when the selected daemon identity is available. The route comes from the installed official protocol helper; native validation accepts only the expected Paseo agent route. Opening the list alone leaves attention unchanged; selecting a conversation lets Paseo apply its normal read behavior. Opening this project’s conversation has been verified locally in Paseo 0.11.2; additional hardware and accessibility scenarios remain in the acceptance checklist.
