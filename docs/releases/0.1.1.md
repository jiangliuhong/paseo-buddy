Paseo Buddy can now start its floating companion automatically when the plugin is installed and enabled on a local macOS daemon.

### Install and use

Enable plugins yourself in Paseo Settings, then install this source:

```text
git:jiangliuhong/paseo-buddy
```

Or use the CLI:

```sh
paseo plugin add git:jiangliuhong/paseo-buddy --ref v0.1.1
```

The plugin downloads the matching Apple Silicon or Intel ZIP from this GitHub release, verifies its SHA-256 checksum, extracts it into the user's private cache, checks the bundle identifier and code signature, and launches the floating app. No manual DMG download or drag-to-Applications step is needed. The first download is about 100 MB and requires GitHub access; subsequent launches reuse the verified cache. If the download is unavailable, the plugin retries in the background and records progress in its logs.

Disable or remove the plugin to stop its owned desktop process. Reloading it starts the companion again. Quitting from the pill stops the window until the next plugin reload/enable. macOS single-instance handling prevents duplicate current-version windows. A managed window exits when its plugin parent disappears.

### Requirements and limits

Paseo 0.11.1 or later, npm for Git-source dependency preparation, and a local macOS daemon running in the logged-in desktop session. The app is launched on the daemon's machine, so remote Linux/Windows daemons cannot display a window on your Mac.

This remains a preview: the app uses ad-hoc signing and has no Apple Developer signing or notarization. The plugin never deletes quarantine attributes or disables Gatekeeper. Errors from OS launch restrictions are recorded in plugin logs.

Standalone DMG/ZIP downloads remain available. Running counts, completed-unread counts, permission waits, full-name previews, and local daemon reconnect continue to work. There are no completion system notifications or conversation deep links yet.
