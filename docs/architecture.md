# Architecture

## Runtime boundaries

- `index.server.ts` and `server/`: Node-only daemon plugin, read-only paginated snapshot RPC, settings, native download/build/process controller and public SDK observation.
- `index.client.tsx` and `client/`: Paseo-hosted settings UI using official `useRpc`, `useSettings` and native settings components. No DOM, Node or compiler access from the client.
- `shared/`: runtime-neutral Zod settings/RPC contracts and normalized Agent types.
- `server/native-source.ts`: complete embedded Swift/AppKit source, included in the server bundle. The native child receives normalized state/events/action results on stdin; stdout carries READY and a single bounded mark-read command shape. No Electron app or downloaded runtime remains.

The SDK declarations in `@getpaseo/plugin`/`@getpaseo/client` 0.11.1 and installed Paseo 0.11.2 define the settings and lifecycle APIs used here. No unsupported deep links or lifecycle fields are introduced.

## Agent state and reconnect

`shared/agent-state.ts` (re-exported by `server/agent-state.ts`) preserves the existing semantics: only unarchived `running` agents with no permissions count as running. Pending permissions produce `waiting_permission`. Idle/closed agents count as `completed_unread` only when `requiresAttention`, `attentionReason === "finished"` and no pending permissions agree. `activeTurn` supplies turn identity/time. Project/workspace placement comes from directory entries and survives metadata-omitting status updates for the same workspace, including idle/read periods between turns; explicit null/fresh snapshots replace metadata. Unarchived idle agents retain metadata internally but stay out of the displayed list. Live directory growth is bounded by the same 5,000-entry limit as hydration. Opening Buddy never automatically clears attention; an explicit Mark as read action is described below.

`server/live-agents.ts` runs in the plugin's Node process. It reads a credential-free explicit loopback endpoint from the selected Paseo home's PID file and the existing local credential. It uses the public SDK directory subscription and receives snapshots before updates. `server/agent-snapshot.ts` collects subsequent pages in creation order; no partial count is published. Updates arriving during hydration are buffered and replayed over the collected pages, including removals. A newer subscription snapshot supersedes older in-flight results. Missing/repeated cursors, page failures, directories above 5,000 entries or event-buffer overflow clear state and trigger reconnect. Stop aborts pending requests and detaches the listener. `agents.snapshot` RPC uses the same bounded pagination without subscribing.

Disconnects clear agents; reconnect uses fresh discovery and 1–30 second exponential backoff. Rapid subscription failures retain the backoff even if initial hydration succeeds; it resets after at least 30 seconds of hydrated connection uptime. Errors sent to the companion contain no transport details or credentials.

## Multiple hosts

The installed Paseo desktop bundle was inspected in addition to SDK declarations: its plugin client loader supplies `useHosts()` and `getPaseoClient(serverId)`. The published SDK JavaScript alone does not export these runtime-injected functions. `client/host-monitor.tsx` mounts a headless sidebar footer component to receive the configured host list. Once mounted, the observer belongs to the installation lifetime and continues when the sidebar unmounts; host-list changes are received while the component is mounted and reconciled on remount. It starts when Paseo first mounts this sidebar contribution, not from the daemon alone. Existing known hosts are rechecked through `getPaseoClient` on each tick, including when sidebar host-list observation is unmounted.

`client/host-observer.ts` borrows online APIs without disposing or closing them, owns only its directory/timeline subscriptions, hydrates bounded complete snapshots, buffers concurrent updates and retries each host independently with 1–30 second backoff. Connection/API replacement invalidates old subscriptions and state. Only live terminal events with explicit turn IDs notify. Shared normalization/pagination stay runtime-neutral; client code imports no Node modules. The relay carries normalized display metadata and live notification identities, never paths, credentials or connection endpoints.

`hosts.publish` uses the existing installation-scoped plugin RPC to the local daemon. There is no new listener. `server/host-relay.ts` holds one publisher lease, monotonic per-session sequencing, bounded deduplication and 15-second heartbeat expiry. Competing client installations cannot interleave snapshots while a lease is active. Disabling the client contribution releases its lease; a crash expires it. Up to 64 hosts and 5,000 total agents are supported. Oversized agent sets become unavailable rather than publishing a partial aggregate. Local daemon observation remains authoritative and is not double-counted when the client also lists it. Remote disconnects clear only the affected host. The native list shows offline/connecting host summaries; badges count available agents and do not imply disconnected hosts are empty.

Host-qualified UI keys prevent agent-ID collisions. Deep links use original agent IDs and their owning server IDs. Native read commands resolve these UI keys back to local agents only. The borrowed high-level API has no supported attention mutation; remote cards offer Open in Paseo but hide Mark as read. No low-level credential extraction or guessed remote RPC is used. Local read controls retain the compatibility adapter described below. Client closure/lease expiry leaves only local state; remote notifications missed without the client observer are not replayed.

## Completion notifications

`server/turn-notifications.ts` observes public live-only timeline subscriptions for running agents (including permission waits), retaining each watch until removal/archive, snapshot replacement or disconnect. Status/attention snapshots never produce notifications. Only `turn_completed`/`turn_failed` carrying an explicit `turnId` are accepted; cancellation, permission events, missing IDs and history are ignored. SHA-256 of `[serverId, agentId, turnId]` identifies (legacy observers without server identity retain `[agentId, turnId]`) a notice, independently of outcome. The latest 10,000 identities survive transport reconnects in Node memory; no credentials or error diagnostics enter notices. Events before watch establishment or during a disconnect are not backfilled.

The pill context menu contains only Quit Paseo Buddy and offers no notification authorization request. Existing macOS authorization remains required for delivery. Background events never prompt or activate Paseo. The native child validates notices and retains the most recent 1,024 identities in its preferences domain across restarts, without names or conversation content. Each identity gets at most one delivery attempt in this retention window; denied permission or delivery failure is not retried. Banners depend on macOS authorization/Focus settings. No historical notification backlog is replayed after enabling permission.

## Conversation navigation

The installed Paseo 0.11.2 bundle registers the `paseo` scheme and uses the same `@getpaseo/protocol/agent-deep-link` builder/parser as protocol 0.11.1. The publisher calls that official builder with each agent’s owning server ID and original agent ID; routes never contain endpoints or credentials. `readPaseoServerId` follows the installed daemon's `PASEO_SERVER_ID` override or `$PASEO_HOME/server-id` file, without creating/modifying either. Missing/invalid identity disables navigation, leaving observation working.

AppKit validates scheme/host, exact route shape, lack of credentials/port/query/fragment and matching decoded agent ID before showing an Open in Paseo button. Only explicit button activation calls `NSWorkspace.open`; snapshots and notification arrival cannot activate Paseo. Opening the list never changes attention; a selected conversation follows Paseo's normal read behavior. Desktop routing and keyboard activation require real GUI acceptance.

## Native releases and cache

Activation attempts only a validated cache, without fetching or compiling. The `download` settings action directly authorizes downloading and starting the current release; a second confirmation is not required. `server/native-download.ts` fixes the repository and release tag (v0.1.6), with separate arm64/x64 executable and JSON manifest assets. Downloads use HTTPS, no credentials, manually checked GitHub redirects, a 120-second deadline, 8 KiB manifest and 32 MiB binary limits. The manifest must match the plugin's version, source SHA-256, recipe and architecture; its binary digest must match before publication or execution. SHA-256 is an integrity check trusting the GitHub release publisher, not independent signing or notarization.

A private staging directory receives only the binary, the plugin's exact Info.plist and validated manifest. There is no archive extraction. An atomic rename publishes a verified cache; competing processes reuse only a valid winner. Invalid existing directories are preserved for explicit repair. Download failures clean staging and allow retry. Stop/disable abort downloads. In-process operations serialize per cache/architecture. Normal activation never downloads automatically. Unsupported platforms are rejected before any fetch/process action.

Cache root: `~/Library/Caches/Paseo Buddy/native`. Cache executable, manifest and bundle directories must be regular, non-symlink files/directories with matching source/version/architecture and binary SHA-256 before launch. Legacy Electron caches are neither launched nor removed. No Gatekeeper modification, quarantine removal, administrator access or developer-tool installation occurs.

Developer builds retain the fixed-argv Apple compiler path and legacy prepare/confirm RPC compatibility; the hosted settings UI exposes the download action. `scripts/package-native-release.mjs` cross-compiles both architectures and exports binary/manifest pairs. The tag workflow checks and builds on macOS, uploads artifacts, and publishes a release only after successful checks/builds. All four assets must be available before users can download the matching companion.

## Native process and IPC

The child gets a narrow environment (system PATH, user locale/home, parent identity, appearance path and a fixed native lock path), with no provider credentials or Paseo home. The parent waits for `READY` before starting observation. The inherited stdin pipe carries bounded JSON snapshots, completion/failure notices and action results; full cwd, credential and unrelated fields are stripped. Backpressure retains only the most recent pending snapshot. A separate FIFO retains up to 256 pending notices so snapshot coalescing cannot discard them; additional notices are dropped while the queue is full. Overflow becomes disconnected/empty state rather than a misleading partial count.

AppKit owns a nonactivating accessory `NSPanel`, a pill and native grouped scrolling list. A `flock` on a regular, same-user lock file under the cache root prevents duplicate managed windows. No listener, shell, browser runtime, privilege request or direct daemon access exists in the native process. Its stdout read-action requests are validated and executed only by Node. EOF or lost parent triggers exit; stop aborts build/start, closes observation and terminates only the owned child with bounded graceful shutdown then SIGKILL. An unsuccessful readiness handshake never starts SDK observation.

## Appearance and geometry

The UI uses a content-sized rounded pill with a 44-point height at 1× scale, a monochrome identity section and a trailing toggle section separated by a fine vertical line. There is no middle waveform/count section. Running and unread counts appear together at the top right as red and green corner badges, with red on the left and green on the right. A single badge uses the normal 44-point toggle width; two badges expand it only enough to fit their widths and a 3-point gap without overlap. The white/light or dark system surface keeps a subtle outline and shadow, with neutral hover/keyboard-focus feedback localized to the toggle. Clicking or focusing the pill never draws a blue outline; the custom focus stroke and AppKit focus ring are disabled while keyboard navigation remains available. Expanded content sits in a separate rounded AppKit popover-material surface with grouped agent cards, muted project/workspace metadata, bounded two-line titles and compact elapsed/navigation footers. System colors adapt to light/dark appearance. The expand/collapse chevron is a 14-point vector path with round caps/joins and a 1.8-point stroke in the primary label color, following the supplied ChatGPT toolbar references.

Paseo owns persistent `display` settings. Additive `showIcon`/`showText` booleans default to true and `customText` defaults to Buddy, retaining settings schema version 1 and existing opacity/scale values. Custom text is trimmed, limited to 32 UTF-16 units and rejects control/line-separator characters; empty text is allowed. The settings screen uses the official SettingsSwitch/SettingsInput components, with a draft and explicit save action for text. Hiding text preserves the stored label.

`pillContentLayout` lays out only visible elements, caps drawn label width at 140 points and retains a 44-point minimum clickable width when all content is hidden. Running and unread badges are absent at zero; disconnected state retains an unknown-count dash. Count and preference changes recompute pill width and re-layout against the saved anchor without activating the panel or changing attention. The plugin maintains the existing mode-0600 temporary mirror after hydration; native AppKit validates and polls it once per second. Opacity changes apply to the panel; scale affects text, pill and list bounds. A separate native UserDefaults domain stores the pill anchor. Expansion chooses space above/below and clamps to the current display while keeping the pill anchor; collapse and resizing preserve the anchor where it fits. The pill uses AppKit’s standard hit-testing so it remains clickable after expansion moves its frame; clicking it again collapses the list. Drag and display-change bounds use the full screen frame, including the Dock region. Dragging tracks the pill anchor rather than the whole expanded panel. AppKit window constraints defer to this explicit geometry so the Dock cannot push the pill upward. The list chooses the side with sufficient room and shrinks its scroll area when necessary; it never intersects the pill. The panel uses the floating level so system menus remain above it. Mouse and Shift-F10 menus are positioned in absolute screen coordinates. Menu tracking suppresses drag/layout changes, then reapplies layout against the retained pill anchor on dismissal. Tab focuses the pill, Shift-F10 opens its menu, and panel-level Escape collapses even when a conversation button holds focus. State rebuilds restore a surviving conversation button’s focus without activating a background panel. Existing Electron position storage is left untouched. List scroll position survives state rebuilds, and elapsed labels update without rebuilding the list every second. IPC state bursts coalesce into one render after 50 ms; explicit toggles render immediately. Native list construction is bounded to 30 agent cards per page with keyboard-accessible Previous/Next controls; counts still cover the complete snapshot and paging preserves status grouping. The current page is clamped when agents disappear. Unchanged list documents are reused across collapse/reopen and geometry-only changes; snapshot, scale, page, pending read and error changes invalidate the cache. The pill accepts the first mouse click while inactive. Separate preconfigured fractional/whole-second date formatters avoid resetting the formatter for each elapsed label.

## Remaining acceptance and features

Completion/failure notification and supported conversation navigation code are implemented; system banner delivery and broad hardware/accessibility acceptance remain pending. Local desktop routing to this project’s conversation has been verified. Automated tests cover state, snapshots, reconnect, settings hydration/cleanup, authorization, cache integrity, build cancellation/concurrency and pipe boundaries. Native geometry/model checks compile the actual source without opening windows. Real GUI tests, platform-specific acceptance and public screenshot status are documented separately in `review-readiness.md`.

## Explicit read actions

Completed-unread cards expose Mark as read. Opening the panel alone sends no request. Each request includes a UUID, agent ID and the daemon-provided attention timestamp. The stdout bridge accepts only this strict shape, caps complete/incomplete lines at 2 KiB and input chunks at 8 KiB, limits active reads to eight, suppresses replayed IDs and concurrent reads of one agent, and rejects disconnected/stale/non-unread targets. Action results use a separate 64-message queue prioritized ahead of notices, so snapshot coalescing or notification backlog does not discard them. On response-queue overflow, the oldest response is dropped; native pending timeouts keep the UI recoverable.

The isolated `server/agent-attention.ts` compatibility adapter uses the exported `@getpaseo/client/internal/daemon-client` API pinned at 0.11.1: the high-level SDK has no attention method. Its `clearAgentAttention` implementation and wire contract were verified against installed Paseo 0.11.2. A short-lived loopback client verifies server identity, fetches the agent again, and compares completion state/timestamp before clearing attention. The SDK operation has no conditional compare-and-set field; no such field is invented here. Credentials stay in Node memory. Stop/disable aborts these clients and timeouts are bounded.

The native button disables while pending, reports fixed retry errors inline and never removes an unread card optimistically. Only normal daemon snapshots/updates change list membership and counts. Native pending actions time out after 25 seconds; Node read operations time out after 15 seconds. Both action buttons use a rounded accent-tinted hover background and pointing-hand cursor; keyboard focus is restored by agent/action identity where possible.

The native list measures its rendered stack before fitting the surface between host settings `listMinHeight` (default 140) and `listMaxHeight` (default 360), both integer 100–600 points with minimum ≤ maximum. Both bounds scale with the pill. Physical screen limits can reduce this further. Additive version-1 defaults preserve existing appearance preferences.
